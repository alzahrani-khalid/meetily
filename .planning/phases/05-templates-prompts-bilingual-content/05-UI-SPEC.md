## BlockNote Arabic Configuration (SUMM-04, D-08)

This is the primary UI contract for Phase 5.

### Configuration

```typescript
// When summary_language === 'ar'
const editor = useCreateBlockNote({
  dictionary: ar,  // from @blocknote/core/locales
});

// Wrapper element
<div dir="rtl" style={{ fontFamily: 'Tajawal, sans-serif' }}>
  <BlockNoteView editor={editor} />
</div>
```

### CSS Requirements

1. **Exclude** `@blocknote/core/fonts/inter.css` import when `summary_language === 'ar'`
2. **Include** Tajawal font via parent CSS inheritance (already loaded from Phase 2)
3. BlockNote `dir="rtl"` on wrapper div -- editor inherits direction
4. No `textAlign: "right"` anywhere (per CLAUDE.md RTL Rule 3 -- `forceRTL` / CSS `dir` handles it)

### States

| State | Behavior |
|-------|----------|
| Arabic summary loaded | BlockNote renders with `dictionary: ar`, `dir="rtl"`, Tajawal font |
| English summary loaded | BlockNote renders with default dictionary, `dir="ltr"`, Source Sans 3 |
| Summary language differs from UI locale | Info banner shown above editor (non-blocking, informational) |
| Summary generation in progress | Existing loading state -- no changes |
| Summary generation failed | Existing error state with locale-aware error message from copywriting table |

### Interaction

- Editor is **editable** in both locales (D-08 green path confirmed)
- Slash menu labels appear in Arabic when `dictionary: ar` is set
- Block labels (paragraph, heading, list) appear in Arabic
- Toolbar buttons use Lucide icons (direction-neutral, no text labels affected)

## RTL Considerations

All Phase 5 UI changes must follow CLAUDE.md RTL rules:

1. Template selector dropdown: uses shadcn `Select` component which inherits `dir` from `<html>` -- no manual RTL work needed
2. BlockNote wrapper: explicit `dir="rtl"` based on `summary_language` (NOT `ui_locale`) because summary language is independent (SUMM-01)
3. Info banner (summary language mismatch): uses logical properties (`ps-*`, `pe-*`, `text-start`) per CLAUDE.md Tailwind RTL rules
4. No `textAlign: "right"` or physical margin/padding classes anywhere
